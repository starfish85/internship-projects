# 使用说明（最短上手）

## 0. 前置检查

```bash
# 外接盘是否挂载
ls /Volumes/CodexArchive

# Chrome 是否安装
ls "/Applications/Google Chrome.app"

# 进入项目
cd "/Users/mac/hbx产品爬取/hotel-cn-crawl"
npm install
```

---

## 1. 监控外接盘（温度 / 空间 / SMART）

```bash
npm run disk:monitor
# 或
bash scripts/monitor-external-disk.sh
```

查看结果：

- 外接盘: `/Volumes/CodexArchive/hbx-hotel-crawl/monitor/disk-monitor-latest.txt`
- 本地镜像: `artifacts/logs/disk-monitor-latest.txt`

安装定期监控（默认每 30 分钟，launchd）：

```bash
npm run disk:install-cron
# 自定义间隔（分钟）
INTERVAL_MIN=15 bash scripts/install-disk-monitor-cron.sh
```

告警阈值（默认）：温度 ≥60 警告、≥70 严重；空间 ≥80% 警告。

---

## 2. 用本机 Chrome 登录 HBX

### 推荐方式：独立调试 Chrome（不影响你日常窗口）

```bash
npm run chrome:launch
```

会打开 **单独 user-data-dir** 的 Chrome，带远程调试端口 **9222**，并访问：

`https://app-bedsonline.gta-travel.cn/main?mkt=CN`

**第一次**请在该窗口完成登录：

1. 若跳到登录页，输入账号；密码可用 Chrome 已保存密码自动填充  
2. 登录成功后确认能进入主界面  
3. 不要关掉该调试 Chrome 窗口（后续脚本通过 CDP 连接它）

### 可选：自动填账号密码

```bash
export BEDSONLINE_USERNAME='你的账号'
export BEDSONLINE_PASSWORD='你的密码'
```

> 历史文档中的账号曾出现 API `401 Login Failed`，若自动登录失败，请改用手动 / 已存密码。

### 进阶：复用你「已经登录」的日常 Chrome

1. 完全退出日常 Google Chrome  
2. 执行：

```bash
CHROME_USER_DATA_DIR="$HOME/Library/Application Support/Google/Chrome" npm run chrome:launch
```

注意：该目录同时只能被一个 Chrome 实例占用。

## 3. 验证登录态

```bash
npm run probe:session -- --waitUserMs=120000
```

成功标志：`ok: true` 且 `hasDarwin: true`。

结果文件：

- `data/probe-session-*.json`
- `/Volumes/CodexArchive/hbx-hotel-crawl/probe/`

---

## 4. 探测酒店页面与 API（先探再爬）

```bash
npm run probe:hotel-ui -- --destinationName=北京 --waitUserMs=120000
```

关注 summary 里的：

- `hotelButtonFound`
- `uniqueApiPaths` / `hotelRelatedPaths`
- `searchAttempted`

截图在 `artifacts/screenshots/`。

## 5. FTS 分批采集（已验证通路）

在调试 Chrome 已登录前提下：

```bash
# 北京酒店清单（中+英 FTS，按 hotelCode 合并）→ 外接盘
npm run harvest:fts -- --query=北京 --queryEn=Beijing --destCode=PEK --size=100

# 中国目的地抽样
npm run harvest:fts -- --query=中国 --type=DESTINATION --destCode=CN --size=100
```

批次目录：

`/Volumes/CodexArchive/hbx-hotel-crawl/batches/CN/by-city/<destCode>/<runId>/hotels.jsonl`

## 6. UI 批爬骨架（默认安全）

**只看计划（不写业务批数据）：**

```bash
npm run crawl:batch -- --destinationName=北京 --maxHotels=20
```

**确认执行试点：**

```bash
npm run crawl:batch -- --destinationName=北京 --maxHotels=20 --confirm=true
```

---

## 7. 推荐操作顺序（41 万全量前）

1. `disk:monitor` 确认盘健康  
2. `chrome:launch` + 登录  
3. `probe:session`  
4. `harvest:fts` 多城市试点  
5. 继续抓包锁定 **详情 / 日历价** 接口（见 `docs/API探测记录.md`）  
6. 目的地全量枚举 + 分批落盘  
7. 保持 `disk:install-cron` 监控温度

---

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| `volume_not_mounted` | 重新挂载 CodexArchive |
| CDP 连不上 | 先 `npm run chrome:launch`，确认 9222 |
| `no_darwin_token` | 在调试 Chrome 手动登录后再 probe |
| 登录 401 | 密码失效；改用已存密码或更新凭据 |
| 未找到酒店 Tab | 看 probe 截图与 `uiHints`，补选择器 |
| 抓到 0 酒店 | API 映射未完成；把 `probe-hotel-ui` JSON 用于扩展解析 |
