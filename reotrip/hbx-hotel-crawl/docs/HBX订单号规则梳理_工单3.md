## 背景
AI 语音 bot 在客户报订单号时要做格式预校验、查无此单时要引导客户核对。三个核心渠道里：
- Viator → BR 开头（已知）
- GetYourGuide → GYG 开头（已知）
- **Hotelbeds / Bedsonline (HBX) → 纯数字，但完整规则未知**（已知日本 284 开头，新加坡另有固定数字）

本任务只需把 **HBX 订单号规则**摸清。

## 要交付的结论
1. **HBX 订单号的格式规则**：
   - [ ] 是否纯数字？固定位数还是变长？给出长度分布。
   - [ ] 有没有稳定的**前缀**？是否按地区/国家不同（如日本 284…、新加坡 …）？列出各地区前缀及占比。
   - [ ] 给出一个可用于预校验的**正则**（或几条正则）。
2. **识别字段**：库里如何区分一张订单是 HBX/Viator/GYG？（渠道字段名、取值；订单号字段是哪个）
3. **关键确认**：客户电话里报的"订单号"，和库里查询用的 `channel_order_id` **是不是同一个号**？若不同，差异是什么、能否互相映射？
4. 各渠道订单号样例**脱敏展示**（打码，仅露格式特征，不露完整真实单号）。

## 怎么查（建议）
