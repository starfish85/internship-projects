# NOL 草稿修改 / 修复 Playbook（可复用）

用于 **已存在的 UNPUBLISHED 草稿** 的纠错与补填（预约信息、价格类型韩文、时间段、文案等）。  
与「从零上架」共用安全底线，但 **保存顺序以本文件为准**。

> 用户硬规则沉淀：2026-08  
> （横滨/大阪港/羽田/成田/关西/伊丹 审计修复 + Excel 红字逐条改：东京站/东京港/大阪站）

**这是接送产品 skill 的修改手册，不是门票 skill。** 门票用 `nol-domestic-ticket-listing-helper`，勿混用。

## 0. Excel 红字问题 → 标准动作（批量审计）

表格 `日本接送产品` 里红色备注 = 待修清单。**一次只改一个产品**，改完汇报 → 用户检查 → 再下一个。

| Excel 红字 / 典型表述 | 产品类型 | 标准修复 |
| --- | --- | --- |
| `4个套餐option内时间设置要修正` / `套餐未设置时间` | 任意日本接送 | 4 个 option 时间一律 **`07:00`–`21:30` / 30 分 / 30 段**；验「时间段」行，不是整页乱抓 `HH:MM` |
| `预订所需信息未设置` | 站/港/景点 | 法规页 **代表预约** 填齐；**航班 id 全关**；红字消失 + 临时保存 |
| 同上（机场） | HND/NRT/KIX/ITM | 代表预约 **含航班** id |
| 价格类型英文 / 审计发现 `7seat go` | 任意 | 弹窗改 `N인승 가는/오는`；**临时保存→下一个**；再打开弹窗读 value |
| `大阪站和新大阪站不是同一个站点，文案调整成仅面向大阪站` | 大阪站 | 产品名/选项名/介绍/包含 **去掉 `신오사카역`**，只保留 **`오사카역`** |

**禁止**：看到「时间要修正」就瞎改一半（只剩 `21:00` 一条）还当成功。

## 1. 绝对安全

| 禁止 | 说明 |
| --- | --- |
| **提交审核 / 批准請求 / 승인 요청** | 除非用户**当轮**明确要求提交 |
| 坐标盲点底部栏 | `临时保存` 与 `提交审核` 常并排；只按**精确文案 + DOM**点 |
| 未保存就 `goto` / 切页 / Escape | 会弹离开确认 = 改动将丢 |

**最终保存语义 = 临时保存。** 出现绿 toast / 临时保存提示即可。提交审核按钮仍在是正常的，不是下一步。

## 2. 离开确认弹窗 = 没保存（用户原话）

弹窗文案类似：

```text
有变化 当您离开页面时，更改将丢失。您确定要离开页面吗？
[消除]  [确定]
```

| 含义 | 动作 |
| --- | --- |
| 出现此弹窗 | **当前改动尚未落盘** |
| **消除 / 取消** | 留在当前页，继续先保存 |
| **确定** | 丢弃改动离开 — **禁止**在未完成保存流程时点 |

自动化：任何导航前先检查 body 是否含 `有变化|更改将丢失|确定要离开`；有则点 **消除**，再走保存流程。

## 3. UI 文案对照（简体 / 繁体 / 韩）

伙伴中心语言可能是 **简体**（羽田 2026-08 实测）。脚本/点选必须兼容：

| 含义 | 简体（常见） | 繁体 | 韩文 |
| --- | --- | --- | --- |
| 临时保存 | **临时保存** | 臨時存儲 | 임시저장 |
| 选项表单下一步 | **下一个** | 下個 | 다음 |
| 页级保存后继续 | **保存然后** | 保存然後 | — |
| 提交审核（禁止） | **提交审核** | 批准請求 | 승인 요청 |
| 修改已有选项 | **修改选项** | 修改選項 | 옵션 수정 |
| 新增选项 | **注册/添加选项** | 註冊/添加選項 | — |
| 价格类型入口 | **选择价格类型** | 選擇價格類型 | 가격 타입 선택 |
| 其他价格类型 | **其他价格类型** | 其他價格類型 | 기타 가격 타입 |
| 价格类型完成 | **完成** | 完成 / 완료 | 완료 |
| 代表预约 | **代表预约信息** | 代表預約信息 | 대표 예약 정보 |
| 预约弹窗确认 | **已选** | 已選 | — |
| 打开已有时段编辑 | 时段旁 **⋯**（`aria-label=더 보기`）→ 菜单 **编辑** | 同左 / 設定時間 | — |
| 重复生成时段 | **重复 小时 添加** | 반복 시간 추가 | 반복 시간 추가 |
| 生成时段列表 | **生成**（扩展可能误显示 **一代**） | 생성 | 생성 |
| 时段弹窗保存 | **保存** | 節省 / 완료 | — |

点选策略：先精确匹配当前 UI 文案，再 fallback 其它语言。**不要只认繁体 `臨時存儲`/`下個`** — 简体页会点不到 → 未保存 → 离开弹窗。

## 4. 修改选项的保存顺序（硬规则）

用户多次强调：

> **先点临时保存，再点下一个**

### 4.1 适用场景

- 改价格类型名称/说明
- 改选项名/描述/时段/价格后退出表单
- 打开「修改选项」做了任何编辑

### 4.2 正确顺序

```text
修改选项
  → 改字段（价格类型 / 名称 / …）
  → 【表单底部】临时保存     ← 必须先
  → 【表单底部】下一个       ← 必须后
  → 确认回到选项列表（URL 无 option-form hash，#name 消失）
  → 不应出现「有变化…离开」
```

### 4.3 按钮定位（选项表单打开时）

同时可见多组按钮：

| 位置 | 典型文案 | 宽高约 | 用途 |
| --- | --- | --- | --- |
| 表单 footer | **临时保存** | w≈120 | **优先点这个**（选项级） |
| 表单 footer | **下一个** | w≈600 | 临时保存之后点 |
| 页底 bar | 临时保存 | w≈359 | 列表页/法规页总保存 |
| 页底 bar | 提交审核 | w≈359 | **永不点** |

实现：枚举 `button`，`text===临时保存|臨時存儲` 且可见未禁用；表单打开时 **优先较小宽度** 的临时保存（footer），再点宽按钮 **下一个|下個**。

### 4.4 错误做法（已踩坑）

| 错误 | 结果 |
| --- | --- |
| 只点「下一个」不点「临时保存」 | 可能未持久化；或随后离开弹窗 |
| 只匹配繁体 `臨時存儲`/`下個` | 简体 UI 点空 → 未保存 |
| `page.goto` 切法规/选项且表单脏 | 弹「有变化…」；点确定=丢改 |
| 验证读完价格类型后 Escape 离开 | 若对话框/表单脏 → 离开弹窗 |
| 坐标点底部栏 | 误点提交审核 |

### 4.5 新建选项 vs 修改选项

| 场景 | 入口 | 结束保存 |
| --- | --- | --- |
| **新建** | `注册/添加选项` | 填完后同样建议 **临时保存 → 下一个**；至少保证 **下一个** 落卡 |
| **修改** | `修改选项`（第 N 张卡） | **强制：临时保存 → 下一个** |

新建时用户也可要求同一顺序；修改时不可省略临时保存。

## 5. 标准修复任务配方

### 5.A 代表预约信息（法规页）

```text
1. 打开 /regulations?id=…
2. 点「代表预约信息」打开弹窗
3. 按 id 勾选 required（真实鼠标/label 点击；勿只依赖 el.checked=true）
4. 点「已选」关闭弹窗
5. 页摘要须列出字段；红字「须填写代表预约…」必须消失
6. 点页底「临时保存」
7. 若「保存然后」已启用可再点（推进步骤）；否则仅临时保存
8. 重新打开法规页复核摘要仍在
```

**机场**（羽田/成田/关西/伊丹）必开航班相关 id：

```text
CELLPHONE-required
EMAIL-required
ENGLISH_LAST_NAME-required
ENGLISH_FIRST_NAME-required
DEPARTURE_DATE_TIME-required
ARRIVAL_FLIGHT_NUMBER-required
ARRIVAL_DATE_TIME-required
DEPARTURE_FLIGHT_NUMBER-required
HOTEL_NAME-required
HOTEL_ADDRESS-required
PICKUP_AREA-required
PICKUP_TIME-required
SENDING_AREA-required
BOOKED_TIME-required
KAKAO_TALK_ID-required
MESSAGING_APP_ID-required
NUMBER_OF_PEOPLE-required
NUMBER_OF_SUITCASES-required
```

**车站/港口/景点**：航班 id 保持关闭。

弹窗列表可能虚拟滚动：找不到 id 时滚动可滚动容器再找；用 `scrollIntoView` + 点 label/`[role=checkbox]` 父级。

### 5.B 价格类型英文 → 韩文

目标名称（名称栏，不是说明栏）：

| 方向×车型 | 价格类型名称 | 说明 |
| --- | --- | --- |
| 去程 7 | `7인승 가는` | `7인승 차량` |
| 去程 10 | `10인승 가는` | `10인승 차량` |
| 返程 7 | `7인승 오는` | `7인승 차량` |
| 返程 10 | `10인승 오는` | `10인승 차량` |

**废弃**：`7seat go` / `10seat rtn` 等英文。

```text
对每个选项卡 i = 0..3：
1. 选项列表 → 第 i 个「修改选项」
2. 「选择价格类型」→「其他价格类型」
3. 名称 placeholder 含「销售渠道」/「銷售渠道」→ 填韩文名
4. 说明 placeholder「例) 滿 19…」→ `{N}인승 차량`
5. 勾必需购买 + 代表价（ETC-required / ETC-representative）
6. 「完成」
7. 若选项名被覆盖成说明文案 → 重填完整路线选项名
8. 【临时保存】→【下一个】
9. 确认回列表且无离开弹窗
```

**校验（必做）**：再打开修改 → 价格类型弹窗 → 读名称 input value === 目标韩文。  
列表卡片可能只显示「7座」芯片，**以弹窗存储值为准**。

### 5.C 时间段修复（日本接送硬标准 + 简体 UI 真路径）

**目标（写进 form / 新建 option 都一样）：**

```text
07:00 · 07:30 · … · 21:00 · 21:30
= 30 个唯一时段，首 07:00，末 21:30（不是 21:00 收尾，不是从 09:30/10:00 起）
```

#### 打开时段编辑（已有脏数据时）

```text
修改选项
  → 滚到「时间段」
  → 点右侧 ⋯ 按钮（aria-label「더 보기」）  ← 不是点「21:00」文字本身
  → 固定层菜单点「编辑」（在「删除」上方）
  → 出现「开始时间」弹窗
```

空时段时可能直接有 **「设置时间」** 按钮 → 点它进入同一类弹窗。

#### 生成 30 段（必须点生成，否则会坏成只剩一条）

```text
1. 若列表里已有错误时段（如只 21:00）：逐条点「删除」清空
2. 点「重复 小时 添加」（韩文 UI：반복 시간 추가）
3. 第一个「选择」→ 07:00（先点小时列 07，再分钟列 00；勿点错列导致 00:00）
4. 第二个「选择」→ 21:30
5. 间隔：「分钟」→ 30
6. 点「生成」  ← 扩展可能显示成「一代」；也可用靠近 小时/分钟 的短按钮
   **未点生成 = 禁止点保存**（用户曾截图：只剩 21:00 就是缺生成）
7. 校验：弹窗内约 30 条「删除」行，或唯一时间 07:00…21:30
8. 点弹窗「保存」（不是「关闭」）
9. 表单「时间段」行已是 `07:00 · … · 21:30`
10. 【临时保存】→【下一个】
```

#### 验收时间（防假通过）

- **只信** compact 行：`时间段` 下一行的 `07:00 · 07:30 · … · 21:30`。
- **不信** 整页 `body` 里所有 `HH:MM` 的 first/last（会混进日历/时间戳，曾误报 first=`10:00`）。
- 正则示例：`/时间段\s*\n\s*((?:\d{2}:\d{2}\s*[·.]\s*)*\d{2}:\d{2})/` 再 split 计数。

#### 禁止的错误结果

| 错误结果 | 原因 |
| --- | --- |
| 只显示 `21:00` | 设了结束点但没 **生成** 就保存 |
| 从 `09:30` / `10:00` 起 | 错默认或旧数据未清 |
| 末班 `21:00` 无 `21:30` | 结束时间设错 |
| 脚本报 30 段但 UI 仍一条 | 读了整页时间而非「时间段」行 |

### 5.D 大阪站文案：仅 `오사카역`（禁止新大阪）

用户红字：*大阪站和新大阪站不是同一个站点，文案调整成仅面向大阪站。*

| 字段 | 正确 | 禁止 |
| --- | --- | --- |
| 产品名 | `오사카 시내 호텔 ↔ 오사카역 단독 차량 편도 이동 서비스` | `…오사카역/신오사카역…` |
| 选项名 | `… → 오사카역 편도 이동…` / `오사카역 출발 → …` | 任何 `신오사카역` |
| 介绍/摘要/预约句 | 只写 오사카역 | `오사카역 또는 신오사카역` |
| 包含 TRANSPORTATION | `오사카 시내 호텔 ↔ 오사카역 편도 전용 차량 이동…` | 带 신오사카 的旧句 |

预约句示例：

```text
예약 시 오사카 시내 호텔명/주소, 오사카역 내 승하차 또는 픽업 장소, 이용 시간, 연락 가능한 휴대전화 번호, 열차 정보를 정확히 입력해 주세요.
```

改名后：属性/介绍/法规包含/四选项 全文搜 `신오사카` 应为 0；再 **临时保存**（选项级再 **下一个**）。

### 5.E 仅列表页保全

四个选项都在列表且无表单打开时：可点页底 **临时保存** 一次。不要点提交审核。

## 6. 产品列表打开草稿（防点不进）

- 草稿卡片是 **`div[class*="slot___StyledContainer4"]`**，不是标题小 div。
- **必须 `mouse.click` 卡片中部**；只 `el.click()` 标题节点可能 URL 不变。
- `修复` 常是文案不是 button。
- 打开后确认 `id=` 与韩文标题匹配再改。

## 7. 自动化实现要点

1. **同一时间只连一个 Playwright CDP 进程**；并行会冻页。开工前杀掉残留 `node fix-*` / `audit-fix-*`。
2. 按钮点击：`querySelectorAll('button')` 映射 index/text/disabled/width/y，再精确 click。
3. React 输入：`fill` + native value setter + `input`/`change` 事件。
4. 价格类型名称 placeholder 可能混写：用 `placeholder*=销售渠道|銷售渠道`。
5. 修改循环禁止脏表单直接 `goto`；必须 **临时保存→下一个**。
6. 时段 **未点生成禁止保存**；生成按钮兼容 `생성|生成|一代`。
7. 参考脚本（均在 `nol-listing-automation/`）：
   - `fix-haneda-resv-pt.mjs` / `audit-fix-narita.mjs` / `audit-fix-kix.mjs` / `audit-fix-itm.mjs` — 机场预约+价格类型韩文
   - `fix-tokyo-port-resv.mjs` — 港口预约（无航班）
   - `fix-osaka-station-times.mjs` — 简体时段 UI 真路径（더 보기→编辑→重复小时添加→生成→保存）

## 8. 验收清单（修改任务结束前）

- [ ] 法规页：无红字「须填写代表预约…」；摘要含电话/邮箱/英文名/酒店/上下车等
- [ ] 机场：摘要含航班；站/港：**无**航班字段
- [ ] 四个选项价格类型弹窗存储名 = `N인승 가는/오는`（若本次改了价格类型）
- [ ] 四个选项「时间段」行：`07:00`…`21:30`，**30** 段（用 compact 行验收）
- [ ] 大阪站类：全文无 `신오사카`
- [ ] 每次改选项均 **临时保存 → 下一个**
- [ ] 离开弹窗只点 **消除** 后重存，未点确定丢改
- [ ] **未**点击提交审核 / 批准請求
- [ ] 结束停在选项列表；**一次一个产品**，等用户点头再改下一个
